# 덱 게이트 규약

작성: 2026-09-10 · 근거 라운드: KMB689 Wk10 1블록

## 1. 목적과 적용 원칙

덱 게이트는 PPTX가 계획한 구조·출처·노출 경계·도판 정체·시각 품질을 지키는지 검증한다. 자동 검사는
내용 판정을 보조하며, 형식 차이를 실질 결함으로 오인하지 않도록 실패를 분류한다.

저작 전에 모든 슬라이드를 원칙적으로 다음 두 집합 중 하나에 배정한다.

- **재사용 집합(R):** 원본 슬라이드를 그대로 쓰거나 재배치하고, 승인된 범위에서 병합·개정한 슬라이드
- **신규 집합(N):** 청사진과 해당 주차 자료를 근거로 새로 만든 슬라이드

두 집합은 겹치지 않고 덱 전체를 덮어야 한다. 즉 `R ∩ N = ∅`, `R ∪ N = 전체 슬라이드`다.
Wk10 1블록의 적용값은 **재사용 19장 + 신규 16장 = 35장**, 교집합 0장, 미분류 0장이다.
다른 주차는 계획서에 그 주차의 R·N 개수를 따로 기록한다.

### 학기별 물류 자리의 예외 집합 E

강의실·평가 비율·일정·과제 마감·성적 정책처럼 학기 시작 직전에만 확정되는 내용은, 교수 지시가
있을 때 **교수 직접 입력 집합(E)**으로 분리한다. E는 제목과 위치만 유지하고 본문을 비우며 AI 저작
대상에서 제외한다. 과거값·예시값·임시값을 넣지 않는다. 계획서에는 각 장을
`교수 직접 입력 — 학기 시작 직전`으로 표시한다.

E가 있는 덱의 분할은 `R ∩ N = R ∩ E = N ∩ E = ∅`, `R ∪ N ∪ E = 전체 슬라이드`로 기록한다. E의 빈 본문은
G2·G3의 합격 분모에서 제외하고, G1에서 장수·위치·제목·본문 공란을 확인한다. G4는 과거·임시
물류값 0건, G6는 잘림·겹침·판독 불가 0건을 확인한다. 이후 다른 주차에서 같은 성격의 자리가
발견되면 같은 처리를 적용한다.

## 2. 6게이트 정의와 적용 범위

| # | 게이트 | 적용 범위 | 통과 기준 |
|---|---|---|---|
| 1 | 구조 | 덱 전체 | 총 장수, 구간별 장수, R·N 개수, 원본/N-ID 매핑, 범위 밖 슬라이드 수가 계획과 일치 |
| 2 | 원문 보존 | **재사용 집합 R만** | 슬라이드 단위 정규화 텍스트가 원본 또는 승인된 병합·개정 대조문과 일치 |
| 3 | 신규 근거 | **신규 집합 N만** | 모든 신규 문구·숫자·용어가 청사진과 해당 주차 자료의 출처에 연결되고 출처 없는 항목이 0건 |
| 4 | 정답 누출 | 덱 전체 텍스트와 발표자 노트 | 계획서가 금지한 정답·판정·등가 표현이 0건이고, 허용한 질문형 노출만 지정 위치에 존재 |
| 5 | 도판 정체·실물 | 반입한 결과 도판과 확인 대상 도판 | md5, 픽셀 크기·차이, 범례, 표시 수치, 크롭 문구가 지정본과 일치. 도판을 쓰지 않고 확인 자료가 대기 중이면 `N/A`로 기록하고 합격 분모에서 제외 |
| 6 | 패키지·시각 | PPTX 전체와 전 장 렌더 | ZIP CRC, 내부 관계, 미디어·외부 링크, 슬라이드 크기, 렌더 장수가 정상이고 전 장 육안 검토에서 잘림·겹침·판독 불가가 0건 |

게이트 2와 3은 적용 범위가 겹치거나 비면 안 된다. Wk10에서는 게이트 2가 19장, 게이트 3이 16장을
검사했다. 게이트 5는 P2 도판 꾸러미 대기이고 1블록에 결과 도판을 넣지 않아 `N/A`로 처리했다.

### 상설 교차주차 게이트 W1-X — 감독 신조 정합성

Wk1에서 처음 제시하는 다음 문구를 전 주차의 감독 신조 정본으로 삼는다.

`기준을 세운다 → AI에게 시킨다 → 검증한다 → 결정한다`

하단 문장도 정본의 일부다.

`분석을 직접 하지 말고, 결과를 읽고 검증한 뒤 결정한다.`

앞으로 저작하는 **모든 세션 덱**은 6게이트 뒤에 W1-X를 실행한다. 장별 계획이 요구한 신조 노출
횟수와 위치를 먼저 확인하고, 발견된 모든 신조·recap 문구를 Wk1 정본과 대조한다. 여섯 기법 세션의
recap은 네 단계의 단어·순서·화살표와 하단 문장이 정확히 같아야 한다. 신조를 노출하지 않는 세션도
유사·부분 문구가 임의 변형되어 들어가지 않았는지 0건 검사를 수행하므로 W1-X를 생략하지 않는다.

대조는 G2′와 같은 방식으로 슬라이드의 `<a:t>`를 문서 순서대로 이어붙이고 공백류만 정규화한다.
숫자·별표·기호·구두점·대소문자·철자·문구 순서는 정규화하지 않는다. Wk1 제목은 `감독 신조`,
후속 회고 장은 `감독 신조 recap`으로 역할을 구분할 수 있으나, 본문 정본은 바꾸지 않는다.
불일치는 실질 실패이며 해당 라운드를 전건 롤백한다.

### 기법 세션의 함정 공개 순서

Wk8에서 여섯 기법 세션의 기본 공개 순서를 확정했다. Wk9·Wk10·Wk11·Wk12·Wk13처럼 1블록의
판정 도구를 2블록 사례에 적용하는 세션은 다음 구조를 따른다.

1. **1블록 — 판정 도구:** 일반 원리·질문·실패 유형을 제시하되 해당 사례의 정답과 결과 수치는 주지 않는다.
2. **2.1 — 표면 유인:** 학생이 실제로 판정할 사례와 원자료의 표면값을 처음 본다.
3. **2.2 — 검증 시범:** AI 주장을 검증 대상으로 제시하고, 강사는 이상 징후를 묻되 정답 직전에 멈춘다.
4. **2.3 — 학생 발견:** Exhibit·워크시트를 이용해 학생이 함정과 메커니즘을 직접 찾는다. 화면에는 정답값을 띄우지 않는다.
5. **2.4 — 회수·결정:** 처음으로 정답과 근거를 회수하고, 분석 판정을 사업 결정과 추가 분석 요청으로 바꾼다.

### 배포 시점도 공개 순서다

학생 자료 자체에 함정의 정답·반전·정답 수치가 들어 있으면 **그 자료의 배포 시점**을 G4 공개 경계의 일부로
기록한다. 덱이 답을 감춰도 Handout·Exhibit·워크시트를 먼저 나눠 주면 학생은 같은 답을 미리 보게 되므로,
슬라이드와 배포물의 공개 시점을 따로 보지 않는다.

- 계획서에는 학생 자료별 최초 배포 구간을 `2.1 / 2.2 / 2.3 / 2.4` 중 하나로 지정한다.
- 정답을 담은 자료는 학생 발견 구간보다 앞서 배포하지 않는다.
- 여러 내용을 한 파일에 묶어 일부가 조기 노출되면, 자료를 고쳐도 된다는 승인이 없는 한 배포 자체를 늦춘다.
- G4는 덱·발표자 노트뿐 아니라 계획된 배포 순서도 검사하고, 첫 정답 노출이 계획 위치보다 앞서지 않는지 확인한다.

Wk9에서는 Case Handout 안의 `+9%`가 반전 단서이므로 2.1에 전체 Handout을 배포하지 않고 2.3의 학생 발견
구간에 배포한다. 같은 위험은 Wk11·Wk12·Wk13에서도 자료별로 다시 검사한다.

G4는 덱과 발표자 노트에서 사례별 금지 토큰을 검사하고, 첫 정답 공개 장이 계획 위치보다 앞서지 않는지
확인한다. Wk8에서는 분해·자기선택 함정의 첫 실질 답을 41장까지 보류했다. 세션별 함정은 달라도
`도구 → 표면 유인 → 질문에서 멈춤 → 학생 발견 → 회수·결정`의 공개 순서는 같은 기준으로 쓴다.

## 3. 실패 등급과 처리

### 실질 실패

숫자·문구·기호·구두점·순서·도판 내용처럼 강의 내용이나 학생 배포물의 의미가 달라진 경우다.
실질 실패가 하나라도 있으면 부분 성공을 남기지 않고 해당 저작 라운드 전체를 롤백한다.

### 형식 실패

공백류, 텍스트 런 분할·병합, XML 속성 순서처럼 화면과 내용에 영향이 없는 차이다. 형식 실패는 즉시
실질 실패로 확정하지 않는다. 원본·결과 XML과 렌더를 대조해 오탐 여부를 판정하고 보고한다. 오탐이면
G2′에 따라 산출물을 고치지 않고 검사식과 정정 이력을 고친 뒤 전체 게이트를 다시 실행한다.

## 4. 원문 보존의 대조 단위

`<a:t>` 요소의 개수나 요소별 배열은 대조 단위가 아니다. PowerPoint와 PPTX 처리 도구가 편집·저장 과정에서
텍스트 런을 쪼개거나 합칠 수 있기 때문이다.

재사용 슬라이드마다 다음 순서로 대조한다.

1. XML 문서 순서대로 모든 `<a:t>` 텍스트를 구분자 없이 이어붙여 슬라이드 문자열 하나를 만든다.
2. U+00A0를 U+0020으로 바꾼다.
3. 줄바꿈과 탭을 U+0020으로 바꾼다.
4. 연속 U+0020을 하나로 줄이고 앞뒤 U+0020을 제거한다.
5. 정규화한 원본과 결과 문자열을 비교한다.

정규화 대상은 위 공백류뿐이다. **숫자·별표·기호·구두점·대소문자·철자·문구 순서는 정규화하지 않는다.**
원문의 띄어쓰기·쉼표·자릿수처럼 의미 또는 표기 충실도에 영향을 주는 차이를 별도 규칙으로 임의 보정하지
않는다. 정규화가 검출력을 약화하지 않았는지 단어 삭제와 숫자·구두점 변경 대조군을 함께 실행한다.

## 5. Presentations 스킬 사용 방식

Wk10은 원본 PPTX를 직접 덮어쓰지 않았다. `@oai/artifact-tool`로 BUSS256 64장 원본을 읽기 전용 입력처럼
가져와 별도 프레젠테이션으로 내보냈다.

| 유형 | Wk10 처리 | 다음 주차의 게이트 유의점 |
|---|---|---|
| 원본 재사용 | 원본 슬라이드를 복제해 재배치. 그대로 쓰는 장은 원문을 유지하고, 병합·개정 장은 승인된 유지 문구와 추가 문구를 명시 | 원본 런 구조를 상당 부분 이어받아도 내보내기 과정에서 런 병합·분할이나 끝의 비가시 공백 삭제가 생길 수 있음 |
| 신규 생성 | 원본의 빈 기반 슬라이드를 복제한 뒤 기존 도형을 지우고 새 텍스트·표·편집 가능한 개념도를 네이티브 객체로 작성 | 원본과 대응하는 `<a:t>` 요소 배열이 없으므로 원문 보존 게이트를 적용하지 않고 신규 근거 게이트로 검증 |
| 최종화 | 비공개 빌드 위치에 후보를 내보내고 패키지·레이아웃 검사를 거쳐 최종 PPTX를 생성 | 후보·최종본 해시와 검사 결과를 기록하고, 최종본을 다시 불러와 패키지 무결성을 확인 |
| 시각 검토 | 번들 렌더러로 전 장을 이미지화해 육안 검토 | 자동 경고만으로 실패를 확정하지 않고 실제 잘림·겹침·판독성을 렌더에서 확인 |

원본 복제 장과 신규 장은 런 분할 양상이 다르다. 복제 장도 최종 저장 후 원본과 요소 수가 같다고 가정하지
않는다. 신규 장에는 애초에 요소 단위 원본 대응이 없다. 따라서 다음 주차도 R에는 슬라이드 단위 원문 보존,
N에는 근거 연결을 적용한다.

## 6. Wk10 오탐과 정정

Wk10 1블록 원문 보존 게이트의 최초 강화판은 `<a:t>` 요소 배열을 그대로 비교했다. 재사용 슬라이드 10번과
14번에서 원본 끝의 U+00A0가 각각 하나씩 없다는 이유로 한 차례의 게이트 실패가 발생했고, 지침에 따라
저작분을 전건 격리했다. 두 차이는 화면·강의·학생 배포물에 영향을 주지 않았다.

이 사건을 **형식 실패이자 오탐 1건**으로 재분류했다. 격리본을 복구하고, 원문 보존 게이트를 슬라이드 단위
연결 문자열에 공백류만 정규화하는 방식으로 정정했다. 정정 후 재사용 19장 모두 통과했다. 같은 검사식은
실제 재사용 원문에 주입한 단어 삭제·숫자 변경·구두점 삭제를 모두 검출했다. PPTX 자체는 수정하지 않아
오탐 전후 SHA-256이 `67e2c9870cc34db2415b0a07068cf10d9b0e79d258a1133205954490d04cb678`로 동일했다.

## 7. 라운드 종료 기록

각 덱 라운드는 최소한 다음을 남긴다.

- 최종 PPTX 경로와 SHA-256
- 원본 PPTX·데이터·도판의 정체와 해시
- R·N 개수와 전 장 매핑
- 6게이트 결과, `N/A` 항목과 합격 분모
- W1-X 결과, 계획상 신조 노출 횟수와 실제 발견 횟수
- 자동 경고와 육안 판정의 구분
- 오탐·검사식 변경·롤백·복구 이력
- 재현 가능한 빌드·게이트 도구 또는 실행 조건
