## 4 · 이미지 마크다운 — v5 가드로 차단, 우회 금지

이 파이프라인은 렌더러가 `![alt](path.png)` 를 처리하지 **않도록** 설계돼 있다.
각 주차의 build 스크립트가 **허용목록(`imgs`)** 을 두고, 목록에 있는 것만
`*[x.png 삽입]*` 플레이스홀더로 전처리한다. 목록 밖의 `![](...)` 는 일부러 남긴다.
**허용목록이 학생용/강사용 그림 분리 장치**이기 때문이다.

- v4는 이 문법을 **조용히 무시**했다. Phase H에서 S11 2종을 v4로 재렌더했다가
  그림이 오류 없이 사라졌다(PDF 4p→3p, `word/media` 1→0). 게이트에서 잡아 롤백.
- **v5는 전처리되지 않은 `![](...)` 가 남아 있으면 예외를 던지고 멈춘다.**
  조용한 소실이 불가능해졌다.
- 렌더러에 이미지 지원을 "추가"하면 **허용목록이 무력화되어 강사용 그림이
  학생용에 섞인다.** 그림 하나 살리려다 학생/강사 분리를 깨는 교환이다.
- **가드가 걸리면 우회하지 말고, 해당 주차의 build 스크립트를 통해 렌더할 것.**
  `allowRawImageMarkdown: true` 는 의도적으로 텍스트로 남길 때만 쓴다.

라이브 md 25개가 표준 이미지 문법을 쓴다(Wk4·Wk5·Wk8-13 계열).
플레이스홀더 문법을 쓰는 것은 4개뿐이다.

## 6-1 · ⚠ 노출 별 개수는 **대칭으로** 판정한다 (2026-08-26 추가)

Phase F에서 쓴 규칙은 한쪽 방향뿐이었다 —
*"구 출력에 짝 없는 별이 남아 있고 신 출력에서 정상 서식으로 흡수됐으면 수정."*
역방향을 쓰지 않아 E-6 오라클이 회귀 17건을 "수정"으로 통과시켰고,
배치 A에서 실자산 24건을 교체했다가 전건 롤백했다.

**항구 규칙**: 구·신 각각의 노출된 별 총수를 세어 **신 > 구이면 회귀**로 분류한다.
증감이 0이어도 **위치가 바뀌었으면 대목을 인용해 보고**한다.

**단서 (2026-09-05)**: "신 > 구면 회귀"는 **내용 불변 재렌더에서만** 성립한다.
행·항목을 추가한 라운드에서는 총수 비교가 성립하지 않으므로 (유의도 별 / 범례 별 /
그 외 고아 별)로 분해하고, **고아 별의 증감**으로 판정한다. 유의도 별 증가분은
**추가한 행·칸 수로 회계**가 맞는지 검산한다(맞지 않으면 그 자체가 신호다).

예: R3 라운드 — 총 +36, **고아 별 ±0**, 회계 36 = 11(표5 4행) + 20(표6 4행×2열) + 5(범례)
→ 회귀 아님.

## 6-2 · ⚠ 여러 줄에 걸친 이탤릭 블록 — 정정하지 않고 목록만 남긴다

한 이탤릭이 여러 줄에 걸쳐 열리고 닫히는 md는 **줄 단위 파서에서 어떤 규칙으로도
온전히 처리되지 않는다.** 구 렌더러가 덜 나빠 보였던 것은 우연히 별 두 개를
먹었기 때문이지 옳게 처리해서가 아니다. 고칠 곳은 렌더러가 아니라 **소스 md**다.

돌리지 않는다.** 여러분은 추천시스템 PM이다. 방금 받은 **[AI가 작성한 토픽 해석]** 을 …

## 6-4 · 자리표시자 문법도 가드 대상이다 — **v6로 해결** (2026-08-26)

v5는 `![](...)` 만 막고 자리표시자 `*[여기에 x.png 삽입]*` 는
`imageResolver` 없이 렌더하면 **조용히 버렸다**. Wk3 3건이 그 구멍으로 그림을 잃을 뻔했고,
배치 A의 이미지 보존 게이트(media 1→0)에서 잡혔다.

**v6(511줄)이 두 형태를 모두 막는다.** 실측 확인:

```
자리표시자 → ✅ [render_shared] 그림 자리표시자 1건이 있는데 해결되는 imageResolver 가 없다
표준 md    → ✅ [render_shared] 전처리되지 않은 이미지 마크다운 1건
이미지 없음 → ✅ 정상 렌더 (오탐 없음)
build 경유 → ✅ 그림 embed 2/2, png md5 라이브와 일치
```

**학생본과 강사본은 다른 그림을 쓴다고 가정하고 각각 역산한다.** 두 번 확인된 패턴:

| 자료 | 학생본 png | 강사본 png |
|---|---|---|
| S11 ClassifInterp | `figD_odds_ratios_STUDENT_EN.png` | `figD_odds_ratios_INSTRUCTOR_EN.png` |
| Wk3_02 ai_exhibit | `figWk3_C_five_items_STUDENT_EN.png` | `figWk3_C_five_items_HONEST_EN.png` |

`Wk3_03_verification_worksheet_KEY` 도 `HONEST_EN` 을 쓴다(강사 계열).

## 6-6 · ⚠ 케이스마다 유의수준 기준이 다르다 — 모든 표에 범례를 표마다 명시한다

라이브러리 안에서 **같은 기호가 다른 뜻**이다. 실측(2026-08-26):

| 케이스 | `***` | `**` | `*` |
|---|---|---|---|
| **ReviewResponsePlaybook** | **p<0.001** | p<0.01 | p<0.05 |
| PrivacyLabelsMinimization | p<0.01 | p<0.05 | p<0.1 |
| PrivacyLabelsUtilization | p<0.01 | p<0.05 | p<0.1 |

별 3개의 의미가 **두 자릿수 차이**다. 학생이 케이스를 옮겨 다니면 그대로 오독한다.

**규칙**: 원고 범례를 그대로 옮기고, **본문·Exhibit·교원 노트의 모든 표 하단에 범례를 개별 명시**한다.
"앞 표와 동일" 같은 참조로 생략하지 않는다. 케이스 간 범례 통일은 하지 않는다 —
통일하면 원고와 어긋나고, 그건 우리가 만든 값이 된다.

**검사**: 표가 있는 모든 파일에서 범례 문자열을 뽑아 그 케이스의 원고 기준과 대조.
같은 케이스 안에서 서로 다른 범례가 나오면 FAIL.

- **판정식이 값–별 사이 공백을 안 봄** — Wk3 `β=0.001 ***` 손상을 F-2로 오분류
- **오라클이 별표 닫는 `**` 를 유의도 별로 셈** — 별 개수 위양성
- **오라클이 라인 단위 파싱** — 표 셀 경계를 넘어감
- **가드 A(자리표시자) 미검출** — `![](...)`만 막고 `*[…]*`를 조용히 삼킴 (v6에서 해결)
- **R-G3 "신 > 구면 회귀"의 비대칭** — 내용 추가 라운드에서 위양성 (§6-1 단서로 해소)
- **오라클 잡 목록이 `02_working/` 루트 구 md 사본 참조** — "드리프트 9건"을 오판 (§6-3 규칙으로 해소)
- **범례 검사식이 이스케이프된 `\*` 를 못 넘김** — Exhibit A·E 자체 점검에서 위양성

**규칙**: 검사가 실패하면 **먼저 검사식을 의심한다.** 산출물을 고치는 것은
(a) 검사식이 옳다는 것을 팩트표·정본과 다시 대조해 확정한 뒤, (b) 그래도 산출물이 틀렸을 때만.
G2′ 원칙("오탐이 나면 검사식을 고친다")은 이 라운드까지 열 번 검증됐다.

## 6-8 · 렌더러는 첨자를 신뢰할 수 없다 — 평문 표기를 쓴다

이번 세션에서 첨자 관련 사고가 세 번 있었다:
- **`<sub>it</sub>` 리터럴 노출** (R3 라운드) — 렌더러가 서브스크립트 태그를 처리하지 않아 태그가 PDF에 그대로 찍혔다
- **유니코드 첨자 `ᵢₜ`** — 렌더 결과는 실제로 정상이지만 `pdftotext -layout` 추출이 첨자를 분리해 값·문장이 어긋나 보이는 아티팩트가 생겼다
- **모형식의 유니코드 첨자** — 렌더 결과는 붙어 있지만 텍스트 추출·복사·검색이 불안정하다

**규칙**: 이 렌더러는 첨자(HTML `<sub>` · 유니코드 아래첨자 · MathJax 계열)를 **모두 신뢰하지 않는다.**
변수·모형식은 **평문 표기**로 쓴다.

- 변수: `답변수 (i, t−1)` · `reply_count (i, t−1)`
- 계수: `b0` · `b1` · `beta_0` — 그리스문자·아래첨자 조합 금지
- 고정효과: `mu(i)` · `theta(t)`
- 오차: `eps(i, t)`
- 모형식은 **fenced code block (` ``` `)** 안에 여러 줄로 명시. 한 줄로 밀면 다음 문장과 붙어 보인다

**보정 (2026-09-08)**: 그리스 문자(β·δ·θ·μ·ε)는 이 파이프라인에서 정상 렌더된다 — 확정 본문 KR/EN에서 확인됨.
평문화 대상은 **첨자·위첨자뿐**이며, 그리스 문자를 ASCII로 바꾸지 않는다.
