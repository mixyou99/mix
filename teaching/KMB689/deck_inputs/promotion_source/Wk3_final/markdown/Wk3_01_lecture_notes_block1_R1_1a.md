## Part A · 관리자의 새로운 문해력 (10분)

### A.1 이 강의가 R을 가르치지 않는 이유

빅데이터·AI 시대의 관리자는 코드를 쓸 필요가 없다. AI 어시스턴트에게 지시하면 몇 초 만에 R 스크립트가 만들어지고, 몇 초 더 지나면 그림과 표가 나온다. 코드 생산의 비용은 사실상 0에 수렴했다.

**그러나 결과 판독의 비용은 그대로다.** AI가 생성한 "매출은 광고비에 강하게 반응합니다(β=0.85, p<0.001)"라는 해설을 **믿을지 말지 결정**하는 것은 여전히 사람의 몫이며, 그 결정에는 다음이 필요하다.

- 그림의 축이 정직한가?
- 표의 열이 실제로 무엇을 재고 있는가?
- 표본이 결론을 지탱할 만큼 큰가?
- AI가 놓친 대안 해석은 없는가?
- 결과의 지표가 실제로 결론에 필요한 지표인가?

관리자가 이 판독을 못하면 조직 전체가 AI의 그럴듯한 결과에 끌려다니게 된다. 그래서 이 세션의 목표는 **"쓰지 않고 읽는다"** — 학생이 R 코드를 스스로 작성하는 능력이 아니라, AI가 만든 결과물을 **감독**하는 능력이다.

### A.2 STAR 프레임의 도입

이 강의 전체를 관통하는 프레임이 **STAR**다. 이는 AI가 만든 분석을 관리자가 감독하기 위한 4단계 절차다.

- **S (기준·Standard)**: 결과를 보기 **전에** 무엇을 검증할지 기준을 세운다. "축이 0부터인가?", "표본이 몇 명인가?" 같은 질문 목록을 미리 준비한다.
- **T (시킴·Task)**: AI에게 분석을 시킨다. 명확한 지시와 함께 결과 형식(그림·표·수치)을 지정한다. **결정까지 시키지 않는다.**
- **A (검증·Audit)**: AI가 내놓은 결과를 (S)에서 세운 기준으로 하나씩 확인한다. 이 단계가 판독의 핵심이며, 오늘 배우는 **결과 읽기 3원칙**이 그 도구다.
- **R (결정·Resolve)**: 검증을 통과한 부분만 채택하고, 실패한 부분은 재분석을 요구하거나 결정에서 배제한다.

STAR의 핵심은 **기준을 결과 이전에 세운다**는 순서다. 결과를 먼저 보면 기준이 결과에 맞춰 사후적으로 조정되기 쉽고, 그러면 감독의 의미가 사라진다.

목표: AI가 만든 R 스크립트를 만났을 때, 각 줄이 무엇을 하는지 **읽어낼** 수 있는 최소 어휘를 확보한다. 이 4요소를 넘어가는 문법(반복문, 조건문, 사용자 정의 함수)은 **의도적으로 배제**한다.

주의: AI가 만든 실제 스크립트에는 이 4요소 외의 문법(리스트, 익명함수, 논리 인덱싱 등)이 종종 등장한다. 그럴 때는 그 부분을 **"AI가 수행한 전처리 블랙박스"**로 취급하고, **관리자가 반드시 감사해야 할 결과 산출 부분**만 집중해서 읽으면 된다. 블록2 Exhibit에서 이 감별 방법을 실습한다.

### B.1 할당 · `<-` (6분)

**핵심 개념**: 왼쪽은 **이름**, 오른쪽은 **값**. 화살표는 "값을 이 이름에 담아라"라는 지시다.

```r
result <- 42
name   <- "고객A"
```

첫 줄: `result`라는 이름에 42라는 값을 담아라. 둘째 줄: `name`이라는 이름에 "고객A"라는 문자열을 담아라.

**초보자가 자주 하는 오해 3가지**:

1. **`<-`와 `=`의 차이 무시**: R에서는 둘 다 할당으로 쓸 수 있지만, 관례상 할당은 `<-`, 함수 인자는 `=`로 구분한다. `barplot(x, ylim = c(0, 100))`에서 `ylim = c(0, 100)`은 "인자 이름=값" 표기이지 할당이 아니다.
2. **왼쪽의 이름이 미리 존재해야 한다고 생각**: 그렇지 않다. `result`라는 이름이 없어도 첫 번째 `<-` 실행 순간에 만들어진다.
3. **할당의 방향**: `<-`는 오른쪽에서 왼쪽으로 값이 흐른다. `->`처럼 반대 방향도 문법상 가능하지만 관례가 아니다. 읽을 때는 **왼쪽 이름을 보고 "이 이름에 무엇이 담기는가"를 확인**하면 된다.

**읽는 요령**: 스크립트를 위에서 아래로 훑을 때, `<-`가 있는 줄마다 왼쪽 이름을 잠시 확인한다. 그 이름들이 스크립트의 **재료 목록**이다. 아래쪽에서 그 이름들이 다시 등장할 때 재료가 어떻게 쓰이는지 추적하면 스크립트의 흐름이 보인다.

### B.2 데이터프레임 (8분)

**핵심 개념**: 데이터프레임은 스프레드시트와 유사한 표 형태의 자료구조다. 행은 관측치(예: 고객 한 명, 바구니 하나), 열은 변수(예: 나이, 구매 금액).

R에서 데이터프레임을 다루는 함수 몇 개만 알면 스크립트가 읽힌다.

```r
str(data)      # data의 구조를 요약해 보여준다: 몇 행 × 몇 열, 각 열의 타입
head(data)     # 처음 6행을 보여준다
nrow(data)     # 전체 행 수
ncol(data)     # 전체 열 수
```

**열을 참조하는 두 표기**:

```r
data$price          # $ 표기: data 안의 price 열
data[, "price"]     # [] 표기: 같은 열에 접근하는 다른 방법
```

두 표기는 동일한 결과를 준다. AI가 만든 코드에서 어느 쪽을 쓰든 "특정 열에 접근하는구나"로 읽으면 된다.

**행을 참조하는 표기**:

```r
data[data$price > 100, ]    # price가 100 초과인 행만 골라내기
```

`[행 조건, 열 조건]` 구조다. 콤마 왼쪽이 행, 오른쪽이 열. 위 예시는 "price가 100 초과인 모든 행, 모든 열"을 뜻한다. 콤마 오른쪽이 비어 있으면 "모든 열"이다.

**데이터프레임과 유사하지만 다른 자료구조**:

R에는 데이터프레임 외에 벡터(1차원 수열), 리스트(길이가 다를 수 있는 원소들의 모음) 같은 구조도 있다. 관리자가 스크립트를 읽을 때는 정확한 구조 구분보다 **"이것은 표(행×열)인가, 수열(1차원)인가"** 를 파악하는 감각이면 충분하다. 정확한 판단은 스크립트가 `str()`이나 `head()`로 인쇄한 결과를 보면 확인할 수 있다.

**초보자가 자주 하는 오해**:

- **`data$price`가 무엇인지 모호**: `data$price`는 **하나의 열 전체** — 1,000개 관측치가 있으면 길이 1,000의 숫자 수열이다. 하나의 숫자가 아니다.
- **데이터프레임 = 스프레드시트라고 생각**: 유사하지만 완전히 같지 않다. 스프레드시트는 셀 단위로 수식을 넣을 수 있지만 데이터프레임은 열 단위 연산이 표준이다. 관리자 수준에서는 "행×열 표"라는 인상만 가지면 된다.

### B.3 파이프 · `|>` (6분)

**핵심 개념**: 왼쪽 결과를 오른쪽 함수의 **첫 번째 인자**로 넣어준다. 여러 처리 단계를 자연어처럼 순차 배열할 수 있게 한다.

파이프가 없는 R 코드는 이렇게 쓴다.

```r
summarize(filter(data, price > 100), mean_price = mean(price))
```

읽으려면 안쪽 함수부터 바깥쪽으로 나가야 한다. 첫 번째로 `data`를 `filter`로 걸러 `price > 100`인 행만 남기고, 그 결과를 다시 `summarize`로 요약해 `mean(price)`를 `mean_price`라는 이름으로 얻는다. 함수 3개가 중첩되어 있어 눈이 안팎을 왕복해야 한다.

파이프를 쓰면 이렇게 다시 쓸 수 있다.

```r
data |>
  filter(price > 100) |>
  summarize(mean_price = mean(price))
```

읽는 순서가 위에서 아래로, 왼쪽에서 오른쪽으로 흐른다. "data를 가져와서 → price 100 초과로 걸러서 → mean_price라는 이름으로 평균을 낸다." **자연어와 같은 순서**다.

**파이프의 규칙**:

- 왼쪽 결과가 오른쪽 함수의 **첫 번째** 인자가 된다.
- 그래서 오른쪽 함수 호출에서는 첫 번째 인자를 생략한다.
- 여러 단계를 연결할 수 있다. 각 단계의 결과가 다음 단계의 첫 번째 입력이 된다.

**읽는 요령**: 파이프가 있는 코드를 읽을 때는 **왼쪽 이름을 주어로, 각 파이프 뒤 함수를 동사로** 생각하라. `data |> filter(...) |> summarize(...)`는 "데이터가, 걸러지고, 요약된다"로 읽힌다.

**R의 두 가지 파이프**: R에는 옛 파이프 `%>%`와 최근 표준 파이프 `|>`가 있다. 입문 수준에서는 두 파이프 모두 "왼쪽 결과가 다음 처리 단계로 전달되는 흐름"으로 읽을 수 있다. 다만 두 연산자의 세부 문법은 완전히 같지는 않으므로 AI 코드에서 어느 쪽이 쓰이든 같은 흐름으로 읽되, 세부 동작이 정확히 동일한지는 별도로 확인해야 한다.

### B.4 함수 호출 (10분)

**핵심 개념**: `함수이름(재료, 옵션1 = 값1, 옵션2 = 값2)`. 함수는 재료(첫 번째 인자)를 받아 처리한 뒤 결과를 돌려준다.

관리자가 자주 만나게 되는 함수 형식 3가지:

**(1) 요약 함수**

```r
mean(data$price)
summary(data)
```

`data$price`의 산술평균, `data` 전체의 요약통계량(최솟값·1분위수·중앙값·평균·3분위수·최댓값). 특별한 옵션 없이 재료 하나만 받는다.

**(2) 모델 함수**

```r
lm(price ~ size + rooms, data = data)
```

`lm`은 선형 회귀(linear model). 물결(`~`)의 **왼쪽은 결과 변수(종속)**, **오른쪽은 예측 변수(독립)**. 위 예시는 "price를 size와 rooms으로 설명하는 회귀 모형을 data라는 데이터프레임 위에서 적합하라"로 읽힌다.

물결의 의미가 회귀 이해의 핵심이다. `y ~ x`는 "y를 x로 설명한다"이지 "y와 x의 관계"라는 대칭 표현이 아니다. 이 방향성이 회귀 계수를 해석할 때 결정적이다.

**(3) 시각화 함수**

```r
barplot(x, ylim = c(0, 100), col = "steelblue")
```

`barplot`은 막대그래프. 첫 번째 인자 `x`가 재료(막대 높이), `ylim`은 y축 범위 옵션, `col`은 색 옵션.

`ylim = c(0, 100)`에서 `c()`는 "값들을 하나로 묶는" 함수로, `c(0, 100)`은 "0과 100이라는 두 값의 쌍"이다. y축이 0에서 100까지 그려진다는 뜻이다.

**옵션의 위치**: 함수 이름 뒤 괄호 안에는 재료가 먼저 오고, 옵션이 뒤에 온다. 옵션은 `이름=값` 형태로 쓴다. 옵션의 순서는 원칙적으로 자유롭지만 관례상 재료 → 축 옵션 → 색·라벨 옵션 순으로 쓴다.

**중요**: `ylim` 인자에 어떤 값이 들어가느냐가 그림의 인상을 결정적으로 바꾼다. `ylim = c(0, 100)`과 `ylim = c(70, 90)`은 같은 데이터를 완전히 다르게 보이게 만든다. 관리자는 이 인자값을 반드시 확인해야 한다.

### B.5 스크립트 한 줄씩 읽기 연습 (5분)

다음은 (mba.csv와 무관한) 가상의 짧은 스크립트다. 4요소로 분해해 읽어보자.

```r
sales      <- read.csv("regional_sales.csv")
top_region <- sales[sales$revenue > 1000000, ]
avg        <- mean(top_region$revenue)
barplot(top_region$revenue, ylim = c(0, 5000000))
```

- 1행: `sales`라는 이름에 CSV 파일을 담는다. (**할당** + **함수 호출**)
- 2행: `sales` 중 `revenue`가 100만 초과인 행만 골라 `top_region`에 담는다. (**할당** + **데이터프레임 행 참조**)
- 3행: `top_region$revenue`의 평균을 `avg`에 담는다. (**할당** + **함수 호출**)
- 4행: `top_region$revenue`를 y축 범위 [0, 5000000]의 막대그래프로 그린다. (**함수 호출** + **`ylim` 옵션**)

**핵심**: 각 줄이 무엇을 만들고(왼쪽 이름), 무엇을 재료로 쓰는지(오른쪽 표현)만 파악하면 스크립트 전체가 읽힌다. 학생이 이 코드를 **작성할** 필요는 없다. **읽기**만 하면 된다.

**실제 AI 스크립트에서 만날 수 있는 것**: AI가 만든 스크립트에는 위 4요소 외의 문법이 등장하기도 한다. 예를 들어 데이터가 표 형태가 아니라 리스트 형태로 저장되어 있으면 `lapply`, `unlist`, `strsplit` 같은 함수가 등장한다. 이런 함수는 **관리자가 문법을 다 이해할 필요는 없다**. 대신 (1) 어느 부분이 데이터 전처리(즉 원자료를 분석 가능한 형태로 정리하는 작업)이고 (2) 어느 부분이 결과를 산출하는 결정적 코드인지 구분해, **후자에 감사 노력을 집중**하면 된다. 블록2에서 이 구분을 실습한다.

## Part C · 결과 읽기 3원칙 (25분)

이제 R 스크립트를 읽을 수 있게 됐다. 다음 단계는 스크립트의 **출력물**(그림·표·수치)을 검증하는 것이다.

3원칙은 순서가 있다. 항상 축을 먼저, 다음에 표본, 마지막에 불확실성을 확인한다.

### C.1 축의 원칙 (10분)

**질문**: 축의 범위가 정직한가? 축이 0에서 시작하는가? 축이 절단되어 있다면 실제 값의 차이는 얼마인가?

**왜 이 원칙이 첫 번째인가**: 축은 시각적 인상을 만드는 가장 강력한 조작 지점이며, 동시에 확인 비용이 가장 낮다. y축의 시작·끝 숫자만 보면 되므로 5초면 확인할 수 있다. 이 5초를 안 쓰면 그림이 만든 인상에 사고가 붙잡힌다.

**축 절단(truncation)의 문제**:

막대그래프는 **0에서 시작하는 것이 표준**이다. 이유는 막대의 시각적 길이가 값의 절대 크기를 나타내기 때문이다. 축이 0에서 시작하지 않으면 막대의 길이는 값 자체가 아니라 **최솟값으로부터의 차이**를 나타내게 되며, 이는 인간의 시각 처리 시스템을 오도한다.

**개념 예시** (mba.csv와 무관한 가상 사례):

한 회사의 지역별 시장점유율이 지역A 32%, 지역B 30%, 지역C 28%라고 하자.

- **정직 버전** (`ylim = c(0, 100)`): 세 막대가 서로 비슷한 높이로, 실제 값의 크기감이 정확히 전달된다. 실무 결론: "세 지역의 점유율은 비슷하다."
- **함정 버전** (`ylim = c(27, 33)`): 지역A가 지역C의 두 배가 넘게 보인다. 실무 결론: "지역A가 압도적이다."

두 그림은 **완전히 같은 데이터**다. y축만 다르다. 결론은 정반대다.

**축 원칙의 판독 절차**:

1. y축의 시작값을 확인한다. 0이 아니면 절단된 것이다.
2. y축의 실제 범위(시작–끝)를 확인한다.
3. 그 폭이 데이터의 실제 폭인지, 조작된 폭인지 판단한다.
4. 축이 0에서 시작하는 정직 버전을 상상하거나 요청한다.

**예외 상황**: 절단이 정당한 경우도 있다. 예를 들어 체온 그래프에서 y축을 35°C부터 시작하는 것은 관례적이다(0°C부터 그리면 오히려 오도한다). 그러나 이런 예외는 **관례가 명확한 지표**에서만 성립한다. 일반적인 비율·매출액·시장점유율 같은 지표에서 절단은 거의 항상 의심스럽다.

### C.2 표본의 원칙 (8분)

**질문**: 표본이 몇 개인가? 결론을 지탱할 만큼 큰가? 그 표본이 대표성이 있는가?

**표본 크기의 두 얼굴**:

- **너무 작으면**: 우연한 변동이 진짜 신호로 오인된다. 10명의 고객 중 7명이 만족했다고 해도 표본이 너무 작아, 실제 고객 전체의 만족률이 어느 범위에 있는지 상당히 불확실하다. 다른 10명을 뽑으면 만족자가 5명이나 9명이 나올 수 있다.
- **너무 크면**: 실무적으로 무의미한 미세한 차이도 통계적으로 "유의"해진다. 100만 명의 데이터에서 두 그룹의 클릭률 차이가 0.001%p면 p<0.001로 유의하지만 실무적 의미는 없다.

**표본 판독의 3가지 확인**:

1. **N을 찾는다**: 표나 그림 어딘가에 "N=X" 또는 "n=X"가 있다. 없으면 **의심스러운 신호**다.
2. **N이 결론과 맞는가**: 소집단 비교라면 각 집단의 N도 확인한다. "여성이 남성보다 만족도가 높다(전체 N=1,000)"에서 남성이 30명뿐이라면 그 30명이 결론을 좌우한다.
3. **표본이 대표성 있는가**: N이 커도 편향된 표본이면 소용없다. 예를 들어 슈퍼호스트 표본으로 일반 호스트를 예측할 수는 없다.

관리자는 표준오차를 계산할 필요는 없다. "N이 몇인가"만 확인해도 대부분의 표본 오독을 막을 수 있다. 다만 **N만으로 두 값 간 차이의 통계적 신뢰성을 확정할 수는 없다**는 점을 기억해야 한다. 정확한 판단에는 각 값의 불확실성 구간(신뢰구간·표준오차)과, 두 값이 같은 개체에서 나왔는지 여부(공분산 구조)가 함께 필요하다.

### C.3 불확실성의 원칙 (7분)

**질문**: 결과에 붙은 유의성 표시(별표)와 실무적 크기는 서로 다른 이야기다. 어느 쪽을 보고 있는가?

**유의성과 크기의 구분**:

R 회귀 결과에는 계수 옆에 별표가 붙는다. `***`는 p<0.001, `**`는 p<0.01, `*`는 p<0.05를 뜻한다. 별표가 많을수록 "우연히 이런 결과가 나올 확률이 낮다"는 뜻이지, "효과가 크다"는 뜻이 아니다.

**흔한 착각 3가지**:

1. **별표 3개 = 큰 효과**: 별표는 유의성이지 크기가 아니다. β=0.001 ***도 있고 β=15.4 (n.s.)도 있다. 관리자에게 실무적으로 중요한 것은 **계수의 크기와 실무적 의미**이지 별표 개수가 아니다.
2. **비유의(n.s.) = 효과 없음**: p>0.05는 "우연 가능성을 배제하지 못한다"는 뜻이지 "효과가 없다"는 증명이 아니다. 표본이 작아서 검출력이 부족한 것일 수도 있다.
3. **신뢰구간을 안 본다**: 계수 0.85 (95% CI: 0.02, 1.68)과 계수 0.85 (95% CI: 0.80, 0.90)은 완전히 다른 결과다. 전자는 "효과가 매우 넓은 범위에 있을 수 있다"이고 후자는 "효과가 좁은 범위에 확실히 있다"이다.

**Wk3의 판독 규칙**:

1. **크기를 먼저 본다**: 계수 값, 오즈비, 향상도, 지지도 같은 **실무 단위**의 숫자를 먼저 읽고 그것이 의미 있는 크기인지 판단한다.
2. **유의성을 다음에 본다**: 크기가 의미 있다면 그것이 우연이 아닌지 별표로 확인한다.
3. **신뢰구간이 있으면 폭을 본다**: 폭이 좁으면 안정된 추정치, 넓으면 불안정한 추정치다.
4. **불확실성 정보가 아예 없으면 요구한다**: AI가 그림·표·수치만 주고 신뢰구간이나 오차범위를 주지 않았다면 "이 값의 불확실성은 얼마인가"를 되물어야 한다.

## Part D · STAR 프레임 상세와 블록2 예고 (5분)

### D.1 STAR 4단계 상세

- **S(기준)**: 결과를 보기 전, 오늘의 3원칙을 미리 체크리스트로 만든다. 축은 0부터인가? N은 얼마인가? 유의성과 크기를 구분해서 봤는가? 결과의 지표가 결론에 필요한 지표인가?
- **T(시킴)**: AI에게 분석 지시를 한다. 명확한 재료(데이터), 목적(무엇을 알고 싶은가), 형식(그림·표·요약통계)을 지정한다. **결정까지는 시키지 않는다.** 결정은 관리자의 몫이다.
- **A(검증)**: 결과가 도착하면 (S)의 체크리스트를 하나씩 확인한다. 이 단계에서 "AI에게 되묻기"가 핵심이다. 예를 들어 "이 그림의 y축이 0에서 시작하는가?" 같은 구체적 질문을 다시 던져 확인한다.
- **R(결정)**: 검증 통과한 결과만 결정에 반영한다. 실패한 부분은 (T)로 돌아가 재분석을 요구한다. STAR는 순환 가능하다.

### D.2 블록2 예고

블록2에서 학생은 AI가 만든 실제 분석 산출물 하나를 STAR 4단계로 검증한다. 인턴이 AI 어시스턴트에게 회사 데이터를 주고 "지지도를 계산하고 재고 조정 권고안을 만들어 달라"고 요청해 받아온 결과다. AI는 R 스크립트를 실행했고, 그림을 그렸으며, 자연어 해설과 재고 조정 권고안까지 만들어 주었다.

학생의 과제는 다음이다.

- 이 AI 산출물을 그대로 상부에 보고할 수 있는지 판단한다.
- 오늘 배운 결과 읽기 3원칙과 R 최소 문법 4요소를 도구로 사용한다.
- 세 원칙 중 어느 것(들)이 이 사례에서 결정적으로 작동하는지, 스스로의 검증을 통해 확인한다.

**AI 사용 규칙 (오늘 세션의 4자료 공통)**: 먼저 자신의 기준과 1차 판단을 기록한 뒤, 단계 3 이후에는 AI에게 질문할 수 있다. 다만 AI의 답도 정답이 아니라 다시 감사해야 할 산출물로 취급한다. 최종 결정문은 반드시 학생 본인이 작성한다.
